# Contribuir

Use uma branch por alteração e um pull request com problema, comportamento final e validação. Execute scripts/check.ps1; ao alterar interface, verifique no Android com GPS permitido e negado. Ao alterar previsões, inclua casos que distinguem o comportamento antigo do correto.

Não edite migrações já aplicadas. Não inclua credenciais, dados de sugestões reais, coordenadas pessoais, APKs de teste com outra assinatura nem caches. Atualize os guias quando mudar comandos ou contratos.

Evite enviar propostas de teste para produção. Use SQLite em memória. O template de pull request e os templates de issues registram evidências sem dados pessoais.
